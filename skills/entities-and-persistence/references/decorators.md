# Decorator and repository reference

Verified against `@kinotic-ai/persistence` (KinoticPersistenceDecorators.ts). All
decorators are imported from `@kinotic-ai/persistence`. They are TC39 stage-3
decorators with no runtime behavior — the tooling reads them from the TypeScript AST.

## Class decorators

| Decorator | Applies to | Notes |
|---|---|---|
| `@Entity(multiTenancyType?, entityType?)` | class | Required for persistence. `MultiTenancyType.NONE` (default) or `SHARED`; `EntityType.TABLE` (default) or `STREAM`. No other enum values exist. |
| `@EsIndexConfiguration(config)` | class | Overrides default Elasticsearch index settings/mappings. Rarely needed. |

## Id decorators (exactly one per entity)

| Decorator | Field shape | Notes |
|---|---|---|
| `@AutoGeneratedId` | `id: string \| null = null` | Server assigns the id on save. |
| `@Id` | `sku: string = ''` | Caller supplies the id. |

## Field decorators

| Decorator | Field shape | Effect |
|---|---|---|
| `@NotNull` | any | Server rejects saves where the field is missing or null. |
| `@Text` | `string` | Tokenized full-text indexing (searchable via `search()`). Without it strings are keyword/exact-match. |
| `@Precision(PrecisionType.SHORT\|INT\|LONG\|FLOAT\|DOUBLE)` | `number` | Storage/index precision. Numbers default to INT. |
| `@NotIndexed` | any | Stored and returned, but not searchable/filterable. For blobs. |
| `@Flattened` | `Record<string, ...>` | Dynamic key-value maps indexed as keywords. |
| `@Nested` | `Something[]` | Array elements stay independently queryable (no cross-matching between elements). |
| `@Version` | `version: string \| null = null` | Optimistic locking; stale saves fail with a conflict. |
| `@TenantId` | `string` | With `MultiTenancyType.SHARED`: exposes the row's tenant id on the entity, filled from the authenticated user on save (a user may not set another). A `SHARED` entity is isolated by tenant without it, but an organization-scope service can only write the entity when it declares the field and sets it, and the field is what generates the `<Entity>AdminRepository` that reads across tenants with a `TenantSelection`. |
| `@DateTime` | `string` or `string[]` holding ISO-8601 dates | Stored and queried as a date, so it sorts and range-queries by time. Set it with `new Date().toISOString()`. |
| `@TimeReference` | `timestamp: string = new Date().toISOString()` | With `EntityType.STREAM`: the time-series timestamp field. Pair it with `@DateTime`. |

A `Date` property is rejected by `bun run generate` (`The Date type is not supported because
values travel as JSON`): entities travel as JSON, where a date is an ISO-8601 string. Declare a
date as a `string` with `@DateTime`, never as a `Date` or as epoch milliseconds in a `number`.

## `@Discriminator(propertyName)` — polymorphic fields

Applied to an entity field holding a **discriminated union**; the required argument
names the property inside the union members that identifies the concrete type:

```typescript
// Pet.ts — plain classes, no @Entity
export class Cat { type: 'Cat' = 'Cat'; name: string = ''; lives: number = 9 }
export class Dog { type: 'Dog' = 'Dog'; name: string = ''; breed: string = '' }
export type Pet = Cat | Dog

// On the entity:
@Discriminator('type')
pet?: Pet
```

A bare `@Discriminator` (no argument) is rejected during generation.

## `@Query(statement)` — named queries

Method decorator, only on the `<Entity>Repository` or `<Entity>AdminRepository` subclass
(the files generation never overwrites). One `SELECT` (rows, or an aggregate with
functions and `GROUP BY`), `INSERT`, `UPDATE` or `DELETE` statement of the migration
grammar naming the entity, `:name` parameter binding, a `Promise` return, and an empty
method body filled by `bun run generate`. A query on an admin repository declares a
`TenantSelection` parameter, and one on the tenant-scoped repository must not; a `Pageable`
parameter pages a `SELECT` (generation warns when it is not first or last).

## Repository API (`EntityRepository<T>`)

| Method | Signature | Notes |
|---|---|---|
| `save` | `(entity: T) => Promise<T>` | Returns the saved entity (id populated). |
| `bulkSave` | `(entities: T[]) => Promise<void>` | One batched request. |
| `update` | `(entity: T) => Promise<T>` | Partial: only fields present in the payload change. Without `@Version`, upserts when the entity does not exist. With `@Version`, the version is mandatory (`A Version must be provided when calling update`) and nothing is upserted. |
| `bulkUpdate` | `(entities: T[]) => Promise<void>` | |
| `findById` | `(id: string) => Promise<T \| null>` | `null` when not found. |
| `findByIds` | `(ids: string[]) => Promise<T[]>` | |
| `findAll` | `(pageable: Pageable) => Promise<IterablePage<T>>` | `page.content`, `page.totalElements`. |
| `search` | `(text: string, pageable: Pageable) => Promise<IterablePage<T>>` | A query-string search over the entity's fields: tokenized matches on `@Text` fields, exact values on keyword fields; Lucene query syntax is accepted. |
| `deleteById` | `(id: string) => Promise<void>` | |
| `deleteByQuery` | `(query: string) => Promise<void>` | e.g. `'age < 18'`. |
| `count` | `() => Promise<number>` | |
| `countByQuery` | `(query: string) => Promise<number>` | |
| `syncIndex` | `() => Promise<void>` | Forces index refresh so recent bulk writes are searchable (`save`/`update` already refresh). |
| `namedQuery` | `<U>(queryName: string, queryParameters: QueryParameter[]) => Promise<U>` | What generated `@Query` bodies call. |
| `namedQueryPage` | `<U>(queryName, queryParameters, pageable) => Promise<IterablePage<U>>` | Paged variant. |

Every repository also exposes identity properties: `entityOrganizationId`,
`entityApplicationId`, `entityName`, `entityId`.

Pagination (`@kinotic-ai/core`): `Pageable.create(pageNumber, pageSize, sort?)` for
offset paging (zero-indexed), `Pageable.createWithCursor(cursor, pageSize, sort?)` for
cursor paging.

The generated `<Entity>Repository` constructor is
`new PersonRepository(entitiesRepository?)` — no arguments needed in normal use; it
requires a connected `Kinotic` singleton (`Kinotic.use(PersistencePlugin)` is optional:
it only adds the typed `Kinotic.entities` accessor). The subclass forwards a generated
`shouldValidate` flag to the base: with `validate: true` in `.config/kinotic.config.ts`,
the base repository runs decorator-derived validation client-side before saves and
updates. An entity with `@TenantId` also gets `<Entity>AdminRepository`
(`new PersonAdminRepository()`), whose read, count and delete methods take a
`TenantSelection` (`['*']` or tenant ids) as their first argument and which has no save.

## Deliberately not covered

`Policy`, `Role`, and `EntityServiceDecorators` exist as exports but the authorization
engine that would enforce them is not implemented — do not use them or present them to
users as working features.
